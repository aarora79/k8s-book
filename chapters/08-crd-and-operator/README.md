# Chapter 8: A CRD and an operator

Status: planned. This file is the chapter's plan. The code and the full text come next, following the template in the top-level README.

## What you will build

A custom resource, `McpServer`, and an operator that turns each one into a Deployment and a Service, reports status conditions, and cleans up with a finalizer. Then the same operator rewritten with controller-runtime, to see what the framework takes off your hands. Chapter 11 deploys MCP Gateway Registry's servers through it.

## What the real one does

A CustomResourceDefinition teaches the API server a new type: it serves the new URLs, validates objects against an OpenAPI schema, and stores them in etcd like any built-in type. An operator is a controller for such a type. [controller-runtime](https://github.com/kubernetes-sigs/controller-runtime) and [Kubebuilder](https://book.kubebuilder.io/) package the informer, workqueue and client from chapters 3 and 4 behind a single `Reconcile` function.

## Scope

| Supported | Left out |
| --- | --- |
| A CRD with a schema, a status subresource and printer columns | Conversion webhooks, multiple versions |
| Create and update a Deployment and Service per `McpServer` | Leader election |
| Status conditions, a finalizer | Metrics, webhooks generated by Kubebuilder |

## Build it (planned steps)

1. Write the CRD YAML and use it with curl and `kk` before any controller exists.
2. An operator with client-go: reconcile `McpServer` into a Deployment and a Service with owner references.
3. Status: write `Ready` and `observedGeneration` through the status subresource.
4. A finalizer that deregisters the server before the object goes.
5. Rewrite with controller-runtime and compare line counts and behavior.

## Run it beside the real one

Run both versions against different namespaces and diff the objects they create.

## Break it

1. Make the image unpullable and check that your conditions say so.
2. Remove the finalizer by hand while the operator is down.

## Improving and expanding

1. Easy: add a printer column for the server URL.
2. Medium: add a `v1beta1` version with a different schema.
3. Hard: add a validating rule in the CRD schema with CEL.
